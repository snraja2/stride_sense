# CrashCart: Build Spec for Codex

Put this file in the repo root as `AGENTS.md` (Codex reads it automatically) or paste it as the task prompt.

## 0. Rules for the agent

1. Work phase by phase (Section 4). Finish a phase, run its acceptance commands, commit with the message `phase X: <title>`, then continue.
2. Develop in **mock mode** first (`LLM_MODE=mock`). Assume there is no API key and no network. Only the human runs live-API steps, marked **[HUMAN]**. When you reach one, stop, list exactly what the human must run, and continue with the next mock-compatible phase.
3. Never invent model IDs, prices or measured results. Model IDs come from `app/config.py` and `.env`. Every number in the README must be generated by `tools/make_report.py` from `eval/results.json`. If a result file does not exist, the README says "not yet measured".
4. The pipeline must never read `truth.json`. Only the eval harness and the truth-badge endpoint may. A test enforces this.
5. Never log or print the API key. No telemetry, no third-party scripts or fonts in the frontend, no logos or trademarks other than plain product names.
6. All synthetic data must be labeled synthetic in the UI and README.
7. Keep dependencies minimal. No database, queue, auth, or frontend build step.
8. Write pytest tests for every deterministic module (ingest, cluster, verify, generator, limiter). Tests must run offline.

## 1. Product

CrashCart takes the files of a failed multi-node GPU training job (rank logs, kernel logs, scheduler log, config, one telemetry dashboard PNG) and produces:
- a root cause, separated from symptoms, with a timeline;
- evidence citations (`file:line` plus a verbatim quote), each verified by code against the source files;
- a dry-run remediation runbook and a postmortem in markdown.

Models (all via Nebius Token Factory, OpenAI-compatible API):
- **swarm**: Nemotron 3.5 Lightning, one worker per log chunk, in parallel.
- **eyes**: Nemotron 3 Nano Omni, reads the dashboard PNG.
- **reduce**: Nemotron 3 Ultra, produces the final diagnosis.
- **skeptic** (stretch): Nemotron 3 Super, writes a dissent.

Track: Best Apps and Agents.

Non-goals: executing any remediation, user accounts, persistent databases, audio/video input, multi-job history.

## 4. Phases

### Phase A: Scaffold and mock mode
- Create the layout, `requirements.txt` (`fastapi`, `uvicorn[standard]`, `openai`, `pydantic`, `python-multipart`, `numpy`, `matplotlib`, `pytest`, `httpx`; add `tavily-python` only in Phase L), `.env.example`, `.gitignore`, MIT `LICENSE` (copyright line: `<HUMAN: your name> 2026`). Pin versions with `pip freeze` after install.
- `app/llm.py`:
  - `call(role, messages, **kw)` with: a global `asyncio.Semaphore(CONCURRENCY)`; retry up to 6 times on HTTP 429/500/502/503/504 with `min(20, 2**attempt) + random()` backoff; on 429 set a shared `pause_until` (honor `Retry-After` if present) that all callers await; return the response plus measured latency; accumulate per-role token usage and call counts in a `Metrics` object.
  - `call_stream(role, messages, **kw)` returning an async iterator of text deltas plus final usage when available.
  - `LLM_MODE=mock`: a deterministic fake responder. Swarm: grep-style findings (regex for `Xid|NCCL WARN|Watchdog|OutOfMemory|nan|Traceback|ECC|Link down|not responding|Killed process|SIGTERM|illegal memory|version`). Reduce: picks the earliest cluster with the highest severity and emits a well-formed narrative plus JSON. Eyes: fixed observations. Fake latencies via `asyncio.sleep(0.2-0.8)`.
- Acceptance: `pytest -q` passes; `python -c "import app.llm"` works with no env vars set.

### Phase B: Gate 0 smoke test **[HUMAN runs, Codex writes the script]**
Write `tools/smoke_test.py` (live mode only; it needs the key). It must:
1. List models via `client.models.list()` and print them. Fuzzy-match ultra, lightning, omni and super IDs (case-insensitive). Write suggested values to `.env.generated`.
2. Make one tiny chat call per role (max_tokens 16). Print latency and usage.
3. Test JSON mode on the swarm role, with and without `response_format`; report which works.
4. Test reasoning controls: for swarm and reduce, try (a) no extra body, (b) `{"chat_template_kwargs":{"enable_thinking":false}}`, (c) `{"enable_thinking":false}`. Report whether the request was accepted and whether `reasoning_content` or `<think>` appears.
5. Concurrency test on swarm: fire 8, 16, 24, 32, 48 simultaneous tiny calls. Report success rate, count of 429s, p50/p95 latency; recommend a `CONCURRENCY` value.
6. Vision test: generate a PNG containing the text "RANK 13" with matplotlib, send it base64 to eyes (`{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`), and print whether the model reads it.
7. Write everything to `gate0_report.json` and print a one-screen summary.

**Human action:** create a key at tokenfactory.nebius.com, put it in `.env`, run `python tools/smoke_test.py`, paste the summary back to Codex. If concurrency is under 12, ask Nebius (Discord) for a higher limit and set a lower `CONCURRENCY` meanwhile. Update `.env` and `app/config.py` defaults from the report.

### Phase C: Synthetic incident generator, dashboards, ground truth
`tools/make_incident.py --id <fault_id>|--all --seed 7 --out incidents/` generates one bundle per fault:

```
incidents/<id>/logs/rank_000.log ... rank_063.log   (8 nodes x 8 GPUs, rank = node*8 + gpu)
incidents/<id>/logs/dmesg_node-00.log ... dmesg_node-07.log
incidents/<id>/logs/scheduler.log
incidents/<id>/job_config.yaml
incidents/<id>/dashboard.png
incidents/<id>/truth.json   {fault_id, category, node, gpu, rank, evidence_file, evidence_line, needs_dashboard, notes}
```

Requirements:
- Each rank log is about 300 lines (about 12K tokens), ISO timestamps at the start of each line, a training step line about every 11 s (`step N loss X lr Y tok/s Z gnorm G mem M GB`), a few INFO lines (checkpoint, eval, NCCL init at the top). Total bundle about 800K tokens (estimate chars/4). Keep the noise realistic and varied but deterministic from the seed.
- Common failure shape: at time `T_f` the fault occurs; healthy ranks keep logging until `T_f`, then hang silently; at `T_f + 600 s` every healthy rank prints a `ProcessGroupNCCL ... Watchdog caught collective operation timeout ... 600xxx milliseconds before timing out` message with about 25 traceback lines, then exits. The tail 200 lines of `rank_000.log` therefore contain only symptoms.
- Pinned demo incident `xid79_demo`: node-01, GPU 5, rank 13. `dmesg_node-01.log` contains `NVRM: Xid (PCI:0000:8a:00): 79, pid=..., name=python, GPU has fallen off the bus.` at `T_f` (plus 2-3 neighboring kernel lines). `rank_013.log` ends at `T_f` with no watchdog message. The other 63 rank logs end at `T_f + 600 s`. All other incidents choose the faulty node/GPU from the seed and record it in `truth.json`.
- Fault table (12 incidents; `needs_dashboard` marks the ones where logs alone cannot solve it):

| fault_id | category | Root-cause evidence | Symptoms elsewhere | needs_dashboard |
|---|---|---|---|---|
| xid79_demo | gpu_fell_off_bus | dmesg Xid 79 | 63 NCCL timeouts, rank log ends early | no |
| ecc_dbe | ecc_error | dmesg Xid 48 double-bit error; rank log `uncorrectable ECC error` | other ranks hang then time out | no |
| ib_flap | ib_link_failure | dmesg `mlx5_core ... Link down` repeated; ranks on that node print `NCCL WARN NET/IB ... error 12 ... vendor err 129` | other nodes time out | no |
| oom_one_rank | cuda_oom | one rank prints `torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 2.00 GiB ...` | others time out | no |
| nan_divergence | nan_divergence | one rank shows `gnorm` spike to inf then `loss nan` earliest | all ranks print `FloatingPointError: loss is nan` a step later | no |
| thermal_throttle | thermal_throttle | none in logs; dashboard shows one GPU at 90+ °C with SM clock collapse | all ranks show step time rising from ~11 s to ~27 s; scheduler `DUE TO TIME LIMIT` | **yes** |
| power_cap | power_cap | none in logs; dashboard shows one GPU with low SM clock at normal temperature and flat power | same slowdown | **yes** |
| fs_stall | filesystem_stall | dmesg `nfs: server fs01 not responding, still trying` on one node, starting before `T_f` | all ranks print `saving checkpoint to ...` with no completion, then time out | no |
| nccl_version_mismatch | nccl_version_mismatch | one node's ranks print a different `NCCL version` at init; scheduler log shows that node reimaged with an older image | hang at the first collective after restart | no |
| dataloader_oom_kill | dataloader_oom_kill | dmesg `Out of memory: Killed process ... (pt_data_worker)`; rank log `DataLoader worker (pid N) is killed by signal: Killed` | others time out | no |
| preemption | preemption | scheduler `... preempted by higher priority job`; ranks on that node log `Received signal 15` | others time out | no |
| illegal_access | illegal_memory_access | rank log `CUDA error: an illegal memory access was encountered` plus dmesg Xid 31 MMU fault | others time out | no |

- `tools/make_dashboard.py`: matplotlib, `Agg` backend, 1800x1000 PNG, generic title "GPU telemetry", no third-party branding. Top row: three line charts over time (mean with min/max band) for GPU utilization %, SM clock MHz and power W. Bottom row: three annotated 8x8 heatmaps (rows `node-00..07`, columns `gpu 0..7`, every cell shows its number) for utilization %, temperature °C and SM clock MHz, sampled at `T_f + 120 s`. Do **not** mark or label the faulty GPU; it must be inferable only from the numbers. Fault effects: `xid79`-like faults drive that GPU's utilization to 0; thermal throttle gives temperature above 90 and clock collapse; power cap gives low clock, normal temperature and flat power.
- Tests: generation is deterministic for a given seed; each bundle's `truth.json` evidence line really exists in the named file at the named line; total estimated tokens within 700K-900K; `truth.json` is never copied into any list the ingest module returns.
- Acceptance: `python tools/make_incident.py --all --seed 7` finishes in under 2 minutes and `pytest tests/test_generator.py` passes.

### Phase D: Ingest, stats, clustering, verifier
- `ingest.py`: `load_bundle(path) -> Bundle` with `files` (relative path, kind: `rank_log|dmesg|scheduler|config|dashboard`, rank/node parsed from the filename, lines), a numbered text form (`L00001|...`), a parsed timestamp per line (regex for ISO-like leading timestamps), and `est_tokens = len(text)/4`. Ignore `truth.json` explicitly. Chunk by file: one chunk per file, split only when above 16K estimated tokens (split on line boundaries, keep absolute line numbers). Each chunk has a stable `id`.
- `file_stats`: per file first_ts, last_ts, last step number. `silence_findings(bundle)`: if a rank log's `last_ts` is earlier than the median `last_ts` of rank logs by more than 120 s, emit a deterministic finding (`kind=silence`, severity 4, quote = that file's last non-empty line, with its real line number, why = "log ends N s before peers"). Silence findings go into the cluster stage like worker findings.
- `verify.py`: `verify_quote(bundle, file, line_start, line_end, quote) -> bool`. Normalize whitespace, require the quote (max 200 chars) to appear inside lines `[line_start, line_end]` of that file. No fuzzy matching. Used for worker findings (filter) and reduce evidence (score).
- `cluster.py`: normalize each finding's quote (digits to `#`, hex to `0x#`, collapse whitespace, lowercase, strip `rank`/`node` identifiers) into a key; group by `(kind, key)`. Each cluster has `count`, `files` (up to 10 plus total), `first_ts`, `last_ts`, `severity` (max), and up to 3 exemplars (always include the earliest by timestamp). Sort clusters by severity descending then `first_ts` ascending; cap at 80, but never drop a cluster with count 1 and severity at least 4.
- Acceptance: tests for chunking, timestamp parsing, silence detection (fires on `rank_013` in `xid79_demo` only), cluster dedupe (64 identical watchdog lines collapse to 1 cluster of count 63), verifier accept/reject cases.

### Phase E: Swarm
- `swarm.py`: `scan(chunk, emit)` calls role `swarm` with `prompts/scan.txt` (Appendix A), `temperature=0`, `max_tokens=700`, JSON mode if Phase B found it works; parse the JSON, on parse failure retry once, then return no findings and emit tile state `error`. Drop findings that fail `verify_quote` (grounded filter). Emit `tile` events (state `running` at start; `clean` or `hit` at end with hits, tokens, latency). `run_swarm(chunks, emit)` uses `asyncio.gather` under the limiter.
- Acceptance (mock mode): running the swarm on `xid79_demo` yields at least one finding from `dmesg_node-01.log` containing "Xid", no finding that fails the verifier, and one tile event per chunk.

### Phase F: Eyes (Omni)
- `eyes.py`: base64-encode `dashboard.png`, send as an `image_url` content part with `prompts/dash.txt` (Appendix A), `temperature=0`, `max_tokens=600`. Parse to `{observations:[{id:"O1", claim, entity, metric, time_ref, severity}], summary}`. Feature flag `USE_EYES` (request option, default on). Any exception means observations are empty and a `warning` event is emitted; the run continues.
- Acceptance (mock): returns fixed observations; failure path covered by a test.

### Phase G: Reduce, verification loop, exports
- `reduce.py`: build the user message from `JOB` (scheduler log summary plus `job_config.yaml` excerpt, under 3K tokens), `FILE_STATS`, `CLUSTERS`, and `VISUAL` (the observations). Call role `reduce` with streaming and `prompts/reduce.txt` (Appendix A). Output format: a narrative first, then a line exactly `---JSON---`, then the JSON of Appendix B. Forward text before the delimiter as `narrative_token` events; buffer the rest and parse. Strip `<think>...</think>`; ignore `reasoning_content`.
- Verification: for each evidence item with a file and lines, run `verify_quote`; for dashboard evidence require the `observation_id` to exist. If any fail, call reduce once more with the failed items listed ("fix or remove these; use only exemplar text"), then re-verify. Remove items that still fail, set `verification = {verified, total, failed}`. If no verified evidence supports the root cause, force `verdict="abstain"`.
- `export.py`: `postmortem.md` (summary, timeline, evidence table with file:line, ruled out, runbook) and `runbook.md`. Each runbook command carries a "DRY-RUN, review before running" banner. Reject (drop) commands matching destructive patterns (`rm -rf`, `mkfs`, `dd if=`, `shutdown`, `reboot` unless flagged as a suggestion line, `kill -9`).
- Acceptance (mock): `xid79_demo` produces verdict `diagnosis`, category `gpu_fell_off_bus`, rank 13, all evidence verified; a corrupted evidence quote is detected and removed.

### Phase H: Pipeline, API, SSE, replay, limits, upload
- `pipeline.py`: `run(bundle, options, emit) -> Result`. Order: emit `run_started`; concurrently start the tail baseline (Ultra on the last 200 lines of `rank_000.log`, prompt `tail_baseline.txt`), eyes, and swarm; compute silence findings; cluster; reduce; verify; export; emit `done`. Options: `swarm_concurrency`, `use_eyes`, `baseline`. Stream a `metrics` event every 500 ms (elapsed, tokens processed, tokens per second computed as (prompt + completion tokens completed) / elapsed, cost from the price table, per-role calls and average latency).
- `events.py`: every event is appended to `RUNS_DIR/<run_id>/events.jsonl` with a relative timestamp. `replay(run_id, speed)` re-streams them with the original spacing divided by `speed`.
- Routes (`main.py`): `GET /` (index.html); `GET /healthz`; `GET /api/incidents` (sample bundles: id, title, file count, est tokens, has_dashboard, has_truth); `POST /api/run {incident_id, swarm_concurrency, use_eyes}` returns `{run_id}` and starts a background task; `GET /api/stream/{run_id}` (SSE, with a `: ping` comment every 15 s); `GET /api/replay/{run_id}?speed=1`; `GET /api/report/{run_id}` (final JSON); `GET /api/report/{run_id}/postmortem.md`; `GET /api/source?incident=<id>&file=<relpath>&line=<n>&ctx=15` (returns lines around `n`; resolve the path inside the bundle directory only); `GET /api/truth/{incident_id}` (samples only, used for a post-run "matches planted ground truth" badge); `POST /api/upload` (zip, max 30 MB, text files plus one PNG, reject absolute or `..` paths, reject zip bombs by checking total uncompressed size, estimated tokens under 1.2M).
- `limits.py`: per-IP counter (default 3 live runs per hour) and a global daily cap. When exceeded, return HTTP 429 `{"error":"limit","replay_run_id":"<sample>"}` and the UI offers the replay.
- SSE event types: `run_started{run_id, incident_id, files:[{id,file,kind,rank,node,est_tokens}], total_tokens, has_dashboard}`, `baseline{text, category}`, `tile{id,state,hits,tokens_in,tokens_out,latency_s}`, `metrics{...}`, `clusters{n,top}`, `omni{observations,summary}`, `narrative_token{text}`, `verdict{diagnosis, verification, highlight_tiles}`, `skeptic{...}` (stretch), `done{elapsed_s,cost_usd,truth_match}`, `warning{message}`, `error{message}`.
- Acceptance: `uvicorn app.main:app` in mock mode; `curl -N /api/stream/<id>` shows the ordered events; replay of that run matches; path traversal tests on `/api/source` and upload pass.

### Phase I: Frontend (`app/static/index.html`, vanilla JS + CSS, no external resources)
- Dark "ops console" look with CSS variables. Header: product name, incident picker, **Run live**, **Replay**, upload button, swarm-size slider (4 to 48, maps to `swarm_concurrency`), a stopwatch, a tokens-per-second odometer, a cost chip, and a line "64 GPUs idle, $X/hr (assumed $3.00/GPU-hr, editable)".

Tile states: idle gray, running pulse, clean green, hit amber, error striped, root-cause red (set from `verdict.highlight_tiles`). Hover shows file name. Click opens the source drawer. For uploads with unknown structure, fall back to an auto-fill grid.
- Right: the dashboard image (served from the bundle), Omni's observations as a list, and a card "What most people do: paste the tail of the log" showing the baseline answer. For sample incidents, mark it correct or wrong after the run using `/api/truth`.
- Bottom, verdict panel: streamed narrative, evidence chips (`[E1] rank_013.log:L212`); clicking a chip opens the source drawer scrolled to the line with a flash animation. - Acceptance: manual run in mock mode shows all states; optional Playwright test takes a screenshot after a mock run and asserts the grid has 64 rank tiles and the verdict badge is present.

### Phase J: Evaluation harness
- `tools/run_eval.py --incidents all --systems crashcart,tail,no_eyes,full_ultra --full-limit 4 --out eval/results.json`:

- Live run of `xid79_demo` ends with a verified diagnosis naming node-01, GPU 5, rank 13, citing the dmesg Xid line and the early end of `rank_013.log`, and the tail baseline answers with a timeout-only explanation (record whatever it really says).

## Appendix A: Prompts (copy verbatim into `app/prompts/`)

**scan.txt**
```
You are a log forensics worker examining ONE slice of logs from a failed multi-node GPU training job.
Each line is prefixed "L<number>|". Report only lines that could matter for a post-mortem: errors, warnings, fatal signals, hardware/driver/kernel messages (Xid, ECC, link flaps, thermal/power), NCCL/network warnings, OOM, NaN/Inf, timeouts, restarts, version/config anomalies.
Rules:
- Quote text VERBATIM from a single line (max 160 characters). Never paraphrase inside "quote".
- line_start/line_end are the L-numbers where the quote appears.
- Ignore routine INFO and step lines unless they show an anomaly.
- If nothing is notable, return {"findings": []}.
- Return ONLY JSON: {"findings":[{"line_start":int,"line_end":int,"quote":str,"kind":"error|warning|hardware|network|memory|numeric|timeout|config","severity":1-5,"why":str}]}
- "why" is at most 20 words. Return at most 12 findings; prefer the earliest and most severe.
```

**dash.txt**
```
You are reading a screenshot of a GPU cluster telemetry dashboard for a failed or degraded training job. It has line charts over time and 8x8 annotated heatmaps (rows are nodes, columns are GPUs).
Report concrete observations only, reading the numbers printed in the charts. Identify any GPU or node that deviates from its peers (utilization, temperature, SM clock, power) and when the deviation starts if the charts show it.
Return ONLY JSON: {"observations":[{"id":"O1","claim":str,"entity":"node-XX gpu N" or null,"metric":str,"time_ref":str or null,"severity":1-5}],"summary":str}
Do not guess causes. Do not invent values that are not visible.
```

**reduce.txt**
```
You are the incident commander for a failed multi-node GPU training job. You receive:
(1) CLUSTERS: deduplicated findings with count, files, first_ts, last_ts, severity, and up to 3 exemplar citations (file, line_start, line_end, quote).
(2) FILE_STATS: per-file first/last timestamp and last step.
(3) VISUAL: observations read from a telemetry dashboard screenshot, ids O1.., possibly empty.
(4) JOB: scheduler and config summary.
Task: determine the ROOT CAUSE and separate it from SYMPTOMS. Loud findings repeated across many ranks are often symptoms. Look for the EARLIEST anomaly localized to a single node or GPU that explains them, and check the ordering with timestamps. Failures that never raise an error (slowdowns) may be visible only in VISUAL.
Rules:
- Every factual claim cites evidence ids (E1..). Each evidence item copies file, line_start, line_end and quote EXACTLY from the exemplars in CLUSTERS. For dashboard evidence use file "dashboard.png" and observation_id.
- If the evidence is insufficient or contradictory, return verdict "abstain" and state what additional data would settle it.
- The runbook is a list of DRY-RUN suggestions for a human: prefer cordon/drain of the suspect node, resuming from the last checkpoint, and diagnostics (nvidia-smi -q, dcgmi diag, ibstat, dmesg checks). Never include destructive commands.
Output: first a NARRATIVE (at most 140 words, plain text, citing like [E1]), then a line containing exactly ---JSON--- , then the JSON object that follows the schema given in the next message.
```

```json
  "confidence": 0.0,
  "symptoms": ["str"],
  "timeline": [{"ts": "str", "event": "str", "evidence_ids": ["E1"]}],

  "ruled_out": [{"hypothesis": "str", "why": "str", "evidence_ids": ["E2"]}],
  "runbook": [{"step": 1, "command": "str", "purpose": "str"}],
  "missing_data": "str|null"
}
```
